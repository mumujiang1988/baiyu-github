## 1. 架构总览

### 1.1 极简架构设计

报表查询采用**轻量级后端 + 灵活前端**的极简架构：

```
┌──────────────────────────────────────────────────────┐
│                    前端层 (Frontend)                   │
│  ┌─────────────────────────────────────────────────┐  │
│  │  自定义筛选组件（el-form + el-table）             │  │
│  │  - 支持任意字段、任意操作符                        │  │
│  │  - 内存二次筛选（filter()）                       │  │
│  │  - 实时响应，无后端请求                            │  │
│  └─────────────────────────────────────────────────┘  │
└──────────────────────┬───────────────────────────────┘
                       │ HTTP请求（仅日期参数）
┌──────────────────────▼───────────────────────────────┐
│                  后端层 (Backend)                      │
│  ┌─────────────────────────────────────────────────┐  │
│  │  ReportEngineServiceImpl                         │  │
│  │  - 参数验证（日期格式/顺序/跨度）                  │  │
│  │  - SQL模板解析（${orderDate:columnName}）         │  │
│  │  - 调用SqlFragmentEngine执行查询                 │  │
│  └──────────────────┬──────────────────────────────┘  │
│                     │                                  │
│  ┌──────────────────▼──────────────────────────────┐  │
│  │  SqlFragmentEngine                               │  │
│  │  - 特殊占位符替换                                 │  │
│  │  - ${orderDate:so.FDate} → so.FDate BETWEEN...  │  │
│  │  - SQL安全校验（白名单/危险关键字）               │  │
│  └──────────────────┬──────────────────────────────┘  │
│                     │                                  │
│  ┌──────────────────▼──────────────────────────────┐  │
│  │  JdbcTemplate                                    │  │
│  │  - 原生JDBC查询                                   │  │
│  │  - 连接池管理                                     │  │
│  └─────────────────────────────────────────────────┘  │
└──────────────────────┬───────────────────────────────┘
                       │ SQL执行
┌──────────────────────▼───────────────────────────────┐
│                  数据库层 (Database)                   │
│  - MySQL / PostgreSQL                                │
│  - 仅需索引优化（日期字段）                           │
└──────────────────────────────────────────────────────┘
```

### 1.2 职责划分

| 层级 | 职责 | 技术实现 |
|------|------|---------|
| **前端** | • 渲染自定义筛选表单<br>• 用户输入验证<br>• 内存二次筛选<br>• 分页展示 | Vue3 + Element Plus<br>`Array.filter()`<br>`computed` 属性 |
| **后端** | • 日期范围筛选（唯一SQL条件）<br>• 参数验证与安全防护<br>• 执行数据库查询<br>• 返回原始数据 | Java + Spring Boot<br>`SqlFragmentEngine`<br>JDBC |
| **数据库** | • 存储业务数据<br>• 执行日期范围查询<br>• 提供索引加速 | MySQL 8.0<br>索引：`(order_date)` |

---

### 1.3 核心优势

#### ✅ 优势1：后端极简
- **代码量少**：仅处理日期筛选，逻辑清晰
- **性能高**：减少数据库压力，避免复杂WHERE条件
- **易维护**：无需动态生成SQL片段，降低复杂度

#### ✅ 优势2：前端灵活
- **任意字段**：支持所有返回字段的筛选
- **任意操作符**：等于、不等于、包含、大于、小于等
- **多表条件**：JOIN后的字段也可筛选
- **实时响应**：内存筛选，毫秒级响应

#### ✅ 优势3：解耦设计
- **前后端独立**：前端筛选逻辑变更不影响后端
- **配置驱动**：SQL模板通过JSON配置，无需硬编码
- **可扩展性强**：新增报表只需配置，无需开发

## 2. 核心设计理念

### 2.1 原则1：日期筛选下推到数据库

**原因**：
- 日期范围查询**必须利用数据库索引**加速
- 减少网络传输数据量
- 支持大数据量场景(百万级记录)

**实现**：
```java
// SQL模板中配置日期参数
{
  "query": "SELECT ... FROM t_sale_order WHERE ${orderDate:so.FDate}",
  "params": [
    {
      "name": "orderDate",
      "label": "订单日期",
      "controlType": "daterange"
    }
  ]
}
```

**生成的SQL**：
```sql
SELECT ... 
FROM t_sale_order so
WHERE so.FDate BETWEEN '2026-04-01' AND '2026-04-30'
```

---

### 2.2 原则2：前端内存二次筛选

**原理**：
```javascript
// 1. 后端返回原始数据（已按日期过滤）
const rawData = await fetchReportData({ orderDate: ['2026-04-01', '2026-04-30'] });

// 2. 前端根据用户输入的筛选条件进行内存过滤
const filteredData = rawData.filter(row => {
  return row.customerName.includes(searchText) && 
         row.amount > minAmount && 
         row.status === selectedStatus;
});

// 3. 分页展示
const pagedData = filteredData.slice((pageNum - 1) * pageSize, pageNum * pageSize);
```

**性能分析**：
| 数据量 | 筛选耗时 | 用户体验 |
|--------|---------|---------|
| 100条 | < 1ms | ⚡ 瞬间响应 |
| 1000条 | < 5ms | ⚡ 瞬间响应 |
| 5000条 | < 20ms | ⚡ 流畅 |
| 10000条 | < 50ms | ✅ 可接受 |

**结论**：对于报表场景（通常返回 < 5000条），前端筛选性能完全够用。

---

### 2.3 原则3：特殊占位符语法

**语法**：`${paramName:columnName}`

**示例**：
```sql
-- SQL模板
SELECT * FROM t_sale_order so WHERE ${orderDate:so.FDate}

-- 前端传入参数
{
  "orderDate": ["2026-04-01", "2026-04-30"]
}

-- 后端生成SQL
SELECT * FROM t_sale_order so WHERE so.FDate BETWEEN '2026-04-01' AND '2026-04-30'
```

**优势**：
- ✅ 简洁明了：一行配置完成日期筛选
- ✅ 类型安全：自动验证日期格式
- ✅ SQL注入防护：自动转义特殊字符

### 3.1 核心组件

#### 组件1：ReportEngineServiceImpl

**位置**：`com.ruoyi.report.service.impl.ReportEngineServiceImpl`

**职责**：
- 解析报表配置（JSON）
- 验证参数（日期格式/顺序/跨度）
- 调用 `SqlFragmentEngine` 执行查询
- 记录访问日志

**核心方法**：

##### 方法1：executeReportQuery（执行报表查询）
```java
public PageResult<Map<String, Object>> executeReportQuery(
    String reportCode, 
    Map<String, Object> params, 
    int pageNum, 
    int pageSize
) {
    // 1. 加载报表配置
    Map<String, Object> config = configRepository.findByCode(reportCode);
    
    // 2. 验证并转换参数
    Map<String, Object> validatedParams = validateAndConvertParams(config, params);
    
    // 3. 解析SQL模板
    SqlTemplate parsedTemplate = parseSqlTemplate(config);
    
    // 4. 执行分页查询
    List<Map<String, Object>> rawData = sqlFragmentEngine.executeWithPagination(
        parsedTemplate.query, 
        validatedParams,
        pageNum, 
        pageSize
    );
    
    // 5. 统计总数（带缓存）
    int total = sqlFragmentEngine.countTotal(parsedTemplate.query, validatedParams);
    
    // 6. 构建返回结果
    return new PageResult<>(total, rawData, pageNum, pageSize);
}
```

##### 方法2：validateAndConvertParams（参数验证）
```java
private Map<String, Object> validateAndConvertParams(
    Map<String, Object> config, 
    Map<String, Object> params
) {
    Map<String, Object> validatedParams = new HashMap<>();
    
    // 遍历配置中的参数定义
    for (Map<String, Object> paramDef : parsedTemplate.params) {
        String paramName = (String) paramDef.get("name");
        String controlType = (String) paramDef.get("controlType");
        Object val = params.get(paramName);
        
        // 仅支持 daterange
        if ("daterange".equalsIgnoreCase(controlType)) {
            if (val instanceof List) {
                List<?> dateRange = (List<?>) val;
                
                // 验证日期数量
                if (dateRange.size() != 2) {
                    throw new IllegalArgumentException("日期范围必须包含开始和结束日期");
                }
                
                String startDate = dateRange.get(0).toString();
                String endDate = dateRange.get(1).toString();
                
                // P1-4: 限制日期字符串长度
                if (startDate.length() > 10 || endDate.length() > 10) {
                    throw new IllegalArgumentException("日期格式错误，请使用 YYYY-MM-DD 格式");
                }
                
                // P1-2: 验证日期格式
                if (!isValidDateFormat(startDate) || !isValidDateFormat(endDate)) {
                    throw new IllegalArgumentException("日期格式错误，请使用 YYYY-MM-DD 格式");
                }
                
                // P1-2: 验证日期顺序
                if (startDate.compareTo(endDate) > 0) {
                    throw new IllegalArgumentException("开始日期不能晚于结束日期");
                }
                
                // P1-2: 限制最大跨度（90天）
                try {
                    LocalDate start = LocalDate.parse(startDate);
                    LocalDate end = LocalDate.parse(endDate);
                    long days = ChronoUnit.DAYS.between(start, end);
                    if (days > 90) {
                        throw new IllegalArgumentException("日期范围不能超过 90 天");
                    }
                } catch (Exception e) {
                    throw new IllegalArgumentException("日期格式错误，请使用 YYYY-MM-DD 格式");
                }
                
                validatedParams.put(paramName, val);
            }
        } else {
            // P1-1: 不支持的控件类型，抛出异常
            throw new IllegalArgumentException(
                "报表配置错误：仅支持日期范围筛选（daterange），不支持 " + controlType
            );
        }
    }
    
    return validatedParams;
}
```

##### 方法3：isValidDateFormat（日期格式验证）
```java
/**
 * 验证日期格式（YYYY-MM-DD）
 */
private boolean isValidDateFormat(String dateStr) {
    if (dateStr == null || dateStr.length() != 10) {
        return false;
    }
    // 简单正则：YYYY-MM-DD
    return dateStr.matches("^\\d{4}-\\d{2}-\\d{2}$");
}
```

#### 组件2：SqlFragmentEngine

**位置**：`com.ruoyi.common.jdbc.template.SqlFragmentEngine`

**职责**：
- 解析特殊占位符 `${paramName:columnName}`
- 生成日期范围 SQL 片段
- SQL 安全校验（白名单/危险关键字）
- 执行分页查询

**核心方法**：

##### 方法1：replaceParams（参数替换）
```java
private ParamReplacementResult replaceParams(String sqlTemplate, Map<String, Object> params) {
    StringBuffer result = new StringBuffer();
    Matcher matcher = PARAM_PATTERN.matcher(sqlTemplate);
    
    while (matcher.find()) {
        String paramName = matcher.group(1);
        String columnName = matcher.group(2);  // 可能为 null
        
        Object paramValue = params.get(paramName);
        
        // 检查是否为特殊语法 ${paramName:columnName}
        if (columnName != null && !columnName.trim().isEmpty()) {
            // 日期范围特殊处理
            if (paramValue instanceof List) {
                List<?> dateRange = (List<?>) paramValue;
                if (dateRange.size() == 2 && dateRange.get(0) != null && dateRange.get(1) != null) {
                    // 生成 BETWEEN 子句
                    String startDate = escapeSqlForBetween(dateRange.get(0).toString());
                    String endDate = escapeSqlForBetween(dateRange.get(1).toString());
                    String replacement = columnName + " BETWEEN '" + startDate + "' AND '" + endDate + "'";
                    
                    matcher.appendReplacement(result, Matcher.quoteReplacement(replacement));
                } else {
                    matcher.appendReplacement(result, "");  // 无效值，跳过
                }
            }
        } else {
            // 普通参数替换（保留兼容性）
            String strVal = paramValue.toString();
            matcher.appendReplacement(result, Matcher.quoteReplacement(strVal));
        }
    }
    
    matcher.appendTail(result);
    return new ParamReplacementResult(result.toString(), new ArrayList<>());
}
```

---

##### 方法2：executeWithPagination（分页查询）
```java
public List<Map<String, Object>> executeWithPagination(
    String sqlTemplate, 
    Map<String, Object> params, 
    int pageNum, 
    int pageSize
) {
    // 1. 白名单校验
    validateSqlTemplate(sqlTemplate);
    
    // 2. 参数替换
    ParamReplacementResult replacementResult = replaceParams(sqlTemplate, params);
    String finalSql = replacementResult.getSql();
    
    // 3. 添加分页
    int offset = (pageNum - 1) * pageSize;
    String paginatedSql = finalSql + " LIMIT " + pageSize + " OFFSET " + offset;
    
    // 4. 执行查询
    long startTime = System.currentTimeMillis();
    try {
        List<Map<String, Object>> result = jdbcTemplate.queryForList(paginatedSql);
        
        // 慢查询日志
        long duration = System.currentTimeMillis() - startTime;
        if (duration > slowQueryThresholdMs) {
            log.warn("[慢查询] {}ms, SQL: {}", duration, paginatedSql);
        }
        
        return result;
    } catch (Exception e) {
        log.error("[查询失败] SQL: {}", paginatedSql, e);
        throw new RuntimeException("查询失败: " + e.getMessage(), e);
    }
}
```

## 4. 前端架构详解

### 4.1 核心组件

#### 组件1：ReportQueryView.vue

**位置**：`frontend/src/views/report/ReportQueryView.vue`

**职责**：
- 渲染报表表格
- 显示自定义筛选表单
- 处理用户交互

**核心逻辑**：

```vue
<template>
  <div class="report-query">
    <!-- 1. 自定义筛选表单 -->
    <el-form :inline="true" :model="filterForm">
      <el-form-item label="客户名称">
        <el-input v-model="filterForm.customerName" placeholder="请输入" />
      </el-form-item>
      
      <el-form-item label="订单金额">
        <el-input-number v-model="filterForm.minAmount" placeholder="最小值" />
        <span>-</span>
        <el-input-number v-model="filterForm.maxAmount" placeholder="最大值" />
      </el-form-item>
      
      <el-form-item label="订单状态">
        <el-select v-model="filterForm.status" placeholder="请选择">
          <el-option label="待审核" :value="1" />
          <el-option label="已完成" :value="2" />
          <el-option label="已取消" :value="3" />
        </el-select>
      </el-form-item>
      
      <el-form-item>
        <el-button type="primary" @click="handleFilter">筛选</el-button>
        <el-button @click="resetFilter">重置</el-button>
      </el-form-item>
    </el-form>
    
    <!-- 2. 数据表格 -->
    <el-table :data="pagedData" border>
      <el-table-column prop="orderNo" label="订单号" />
      <el-table-column prop="customerName" label="客户名称" />
      <el-table-column prop="amount" label="订单金额" />
      <el-table-column prop="status" label="状态" />
      <el-table-column prop="orderDate" label="订单日期" />
    </el-table>
    
    <!-- 3. 分页 -->
    <el-pagination
      v-model:current-page="pageNum"
      v-model:page-size="pageSize"
      :total="filteredTotal"
      @current-change="handlePageChange"
    />
  </div>
</template>

<script setup>
import { ref, computed, onMounted } from 'vue';
import { executeReportQuery } from '@/api/report';

// 1. 状态管理
const rawData = ref([]);           // 后端返回的原始数据
const filterForm = ref({});        // 筛选表单
const pageNum = ref(1);            // 当前页码
const pageSize = ref(10);          // 每页大小

// 2. 加载数据（仅传递日期参数）
const loadData = async () => {
  const response = await executeReportQuery('sales_dept_summary', {
    orderDate: ['2026-04-01', '2026-04-30']  // 仅日期参数
  });
  rawData.value = response.rows;
};

// 3. 计算属性：内存筛选
const filteredData = computed(() => {
  return rawData.value.filter(row => {
    // 客户名称筛选
    if (filterForm.value.customerName && 
        !row.customerName.includes(filterForm.value.customerName)) {
      return false;
    }
    
    // 订单金额筛选
    if (filterForm.value.minAmount && row.amount < filterForm.value.minAmount) {
      return false;
    }
    if (filterForm.value.maxAmount && row.amount > filterForm.value.maxAmount) {
      return false;
    }
    
    // 订单状态筛选
    if (filterForm.value.status !== undefined && 
        row.status !== filterForm.value.status) {
      return false;
    }
    
    return true;
  });
});

// 4. 计算属性：筛选后的总数
const filteredTotal = computed(() => filteredData.value.length);

// 5. 计算属性：分页数据
const pagedData = computed(() => {
  const start = (pageNum.value - 1) * pageSize.value;
  const end = start + pageSize.value;
  return filteredData.value.slice(start, end);
});

// 6. 事件处理
const handleFilter = () => {
  pageNum.value = 1;  // 重置页码
};

const resetFilter = () => {
  filterForm.value = {};
  pageNum.value = 1;
};

const handlePageChange = (newPage) => {
  pageNum.value = newPage;
};

// 7. 初始化
onMounted(() => {
  loadData();
});
</script>
```

## 5. 数据流转流程

### 5.1 完整流程图

```
1. 用户打开报表页面
   ↓
2. 前端加载报表配置（元数据接口）
   GET /report/config/metadata/sales_dept_summary
   ↓
3. 后端返回配置（filter_config = null）
   {
     "report_code": "sales_dept_summary",
     "sql_template": {
       "query": "SELECT ... WHERE ${orderDate:so.FDate}",
       "params": [{"name": "orderDate", "controlType": "daterange"}]
     },
     "filter_config": null  // ← 不再返回
   }
   ↓
4. 前端渲染自定义筛选表单
   （不依赖 filter_config，使用硬编码表单）
   ↓
5. 用户选择日期范围，点击"查询"
   ↓
6. 前端发送请求（仅日期参数）
   POST /report/execute/sales_dept_summary
   Body: { "orderDate": ["2026-04-01", "2026-04-30"] }
   ↓
7. 后端验证参数
   - 日期格式：YYYY-MM-DD
   - 日期顺序：start <= end
   - 日期跨度：<= 90天
   ↓
8. 后端生成SQL
   ${orderDate:so.FDate} → so.FDate BETWEEN '2026-04-01' AND '2026-04-30'
   ↓
9. 后端执行查询
   SELECT ... FROM t_sale_order so 
   WHERE so.FDate BETWEEN '2026-04-01' AND '2026-04-30'
   LIMIT 10 OFFSET 0
   ↓
10. 后端返回原始数据
    {
      "total": 1000,
      "rows": [
        {"orderNo": "SO001", "customerName": "张三", "amount": 1000, ...},
        ...
      ]
    }
    ↓
11. 前端接收数据，存入 rawData
    ↓
12. 用户输入筛选条件（客户名称、金额等）
    ↓
13. 前端内存筛选
    filteredData = rawData.filter(row => ...)
    ↓
14. 前端分页展示
    pagedData = filteredData.slice(start, end)
    ↓
15. 用户切换筛选条件
    ↓
16. 重复步骤 13-14（无需后端请求）
```

---

### 5.2 关键节点说明

#### 节点1：参数验证（后端）
**目的**：防止无效输入导致 SQL 错误  
**验证项**：
- 日期格式：`YYYY-MM-DD`
- 日期顺序：`startDate <= endDate`
- 日期跨度：`<= 90天`
- 控件类型：仅支持 `daterange`

---

#### 节点2：SQL 生成（后端）
**特殊占位符**：`${orderDate:so.FDate}`  
**生成规则**：
```
${paramName:columnName} + List[startDate, endDate]
→ columnName BETWEEN 'startDate' AND 'endDate'
```

**示例**：
```
${orderDate:so.FDate} + ["2026-04-01", "2026-04-30"]
→ so.FDate BETWEEN '2026-04-01' AND '2026-04-30'
```

---

#### 节点3：内存筛选（前端）
**筛选逻辑**：
```javascript
rawData.filter(row => {
  // 任意字段、任意操作符
  return row.customerName.includes(searchText) && 
         row.amount >= minAmount && 
         row.amount <= maxAmount && 
         row.status === selectedStatus;
});
```

**性能**：
- 1000条数据：< 5ms
- 5000条数据：< 20ms
- 10000条数据：< 50ms

## 11. 故障排查

### 11.1 常见问题

#### 问题1：日期格式错误

**现象**：`IllegalArgumentException: 日期格式错误，请使用 YYYY-MM-DD 格式`

**原因**：
- 前端传入的日期格式不正确
- 例如：`"2026/04/01"` 或 `"2026-4-1"`

**解决**：
```javascript
// ✅ 正确：使用 YYYY-MM-DD 格式
orderDate: ["2026-04-01", "2026-04-30"]

// ❌ 错误
orderDate: ["2026/04/01", "2026/04/30"]
orderDate: ["2026-4-1", "2026-4-30"]
```

---

#### 问题2：日期跨度过大

**现象**：`IllegalArgumentException: 日期范围不能超过 90 天`

**原因**：用户选择的日期范围超过90天

**解决**：
- 前端限制日期选择器范围
- 提示用户缩小日期范围

---

#### 问题3：前端筛选无响应

**现象**：输入筛选条件后，表格数据未更新

**原因**：
- 未使用 `computed` 属性
- 筛选逻辑有误

**解决**：
```javascript
// ✅ 正确：使用 computed
const filteredData = computed(() => {
  return rawData.value.filter(row => {
    return row.customerName.includes(filterForm.value.customerName);
  });
});

// ❌ 错误：直接赋值
const filteredData = ref(rawData.value.filter(...));  // 不会响应式更新
```

---

#### 问题4：慢查询告警

**现象**：日志中出现 `[慢查询] 150ms, SQL: ...`

**原因**：
- 缺少日期字段索引
- 数据量过大

**解决**：
```sql
-- 添加索引
CREATE INDEX idx_order_date ON t_sale_order(FDate);

-- 优化SQL（避免SELECT *）
SELECT dept_id, COUNT(*), SUM(amount) FROM ...
```
