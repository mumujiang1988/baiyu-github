## P0级问题修复

### P0-1: 前端实现内存二次筛选

**问题描述:**
- 当前所有筛选条件都传递给后端，每次筛选都发起HTTP请求
- 架构要求：后端仅处理日期筛选，其他筛选在前端内存过滤
- 性能影响：网络延迟50-200ms vs 内存筛选<5ms

**涉及文件:**
- `frontend/src/views/erp/report/DepartmentReport.vue` (核心修改)
- `frontend/src/views/erp/report/components/ReportFilter.vue` (需获取筛选值)

**修复步骤:**

#### 步骤1: 添加 rawData 缓存和前端筛选逻辑

在 `DepartmentReport.vue` 中添加以下代码：

```javascript
// Line 200 附近：添加 rawData 缓存
const tableData = ref([])      // 当前页显示的数据（经过前端筛选+分页）
const rawData = ref([])        // 后端返回的完整数据（已按日期过滤）
const loading = ref(false)
const exporting = ref(false)

// Line 237-277：重写 handleQuery 函数
async function handleQuery(queryParams) {
  if (!activeReportCode.value) {
    ElMessage.warning('请先选择报表')
    return
  }
  
  loading.value = true
  try {
    // 构建请求数据：仅传递日期参数给后端
    const requestData = {
      reportCode: activeReportCode.value,
      params: {
        orderDate: queryParams?.orderDate || [],  // 仅传递日期参数
        pageNum: 1,                                // 始终从第1页开始获取
        pageSize: 10000                            // 获取足够多的数据用于前端筛选
      }
    }
    
    const res = await executeReport(requestData)

    if (res.code === 200) {
      rawData.value = res.data.rows || []  // 缓存原始数据
      total.value = rawData.value.length   // 更新总数为原始数据量
      
      // 应用前端筛选（非日期参数）
      applyFrontendFilters()
      
      // 更新 Store
      reportStore.updateData(activeReportCode.value, tableData.value)
      
      // 确保列配置已初始化
      const columns = currentMetadata.value?.columns
      if (columns && columns.length > 0 && visibleColumns.value.length === 0) {
        await initColumns(columns)
      }
    } else {
      handleError(res, '查询报表')
    }
  } catch (error) {
    handleError(error, '查询报表')
  } finally {
    loading.value = false
  }
}

// 新增：前端筛选函数（Line 278 之后）
/**
 * 应用前端筛选条件（非日期参数）
 */
function applyFrontendFilters() {
  let filtered = [...rawData.value]  // 复制原始数据
  
  // 获取用户输入的筛选条件
  const filters = filterRef.value?.getFilterValues() || {}
  
  // 遍历所有筛选条件，排除日期参数（已由后端处理）
  Object.keys(filters).forEach(key => {
    // 跳过日期参数
    if (key === 'orderDate' || !filters[key]) {
      return
    }
    
    const value = filters[key]
    
    // 根据字段类型应用不同的筛选逻辑
    filtered = filtered.filter(row => {
      const rowValue = row[key]
      
      // 字符串类型：模糊匹配
      if (typeof rowValue === 'string') {
        return rowValue.includes(String(value))
      }
      
      // 数字类型：精确匹配或范围匹配
      if (typeof rowValue === 'number') {
        // 如果是范围筛选（minAmount/maxAmount）
        if (key.startsWith('min')) {
          const baseKey = key.replace('min', '')
          return rowValue >= value
        }
        if (key.startsWith('max')) {
          const baseKey = key.replace('max', '')
          return rowValue <= value
        }
        // 否则精确匹配
        return rowValue === Number(value)
      }
      
      // 默认：精确匹配
      return String(rowValue) === String(value)
    })
  })
  
  // 更新总数
  total.value = filtered.length
  
  // 应用分页
  const start = (pageNum.value - 1) * pageSize.value
  const end = start + pageSize.value
  tableData.value = filtered.slice(start, end)
}

// Line 357-369：修改分页函数，调用前端筛选而非重新请求
function handlePageChange(newPage) {
  pageNum.value = newPage
  applyFrontendFilters()  // ← 改为前端筛选
}

function handleSizeChange(newSize) {
  pageSize.value = newSize
  pageNum.value = 1  // 重置到第一页
  applyFrontendFilters()  // ← 改为前端筛选
}

// Line 564-568：修改下钻返回逻辑
function handleDrillBack() {
  if (drillState.value.history.length === 0) {
    ElMessage.info('已经是最顶层')
    return
  }
  
  // 恢复上一级状态
  const previousState = drillState.value.history.pop()
  drillState.value.currentLevel = previousState.level
  drillState.value.params = previousState.params
  
  // 重新应用前端筛选（不重新请求后端）
  applyFrontendFilters()
  ElMessage.success('已返回上一级')
}

watch(
  () => filterRef.value?.getFilterValues(),
  (newFilters, oldFilters) => {
    // 仅在筛选条件实际变化时触发
    if (!oldFilters || JSON.stringify(newFilters) !== JSON.stringify(oldFilters)) {
      // 检查是否仅非日期参数变化
      const hasDateChanged = JSON.stringify(newFilters?.orderDate) !== JSON.stringify(oldFilters?.orderDate)
      
      if (hasDateChanged) {
        // 日期变化：重新请求后端
        pageNum.value = 1
        handleQuery(newFilters)
      } else {
        // 仅非日期参数变化：前端筛选
        pageNum.value = 1
        applyFrontendFilters()
      }
    }
  },
  { deep: true }
)
```

**问题描述:**

```markdown
### 7.4 穿透SQL配置规范

**原则**: 穿透SQL也应遵循"仅使用日期参数"的原则

**示例**:
```json
{
  "levels": [
    {
      "level": 2,
      "name": "销售员明细",
      "sql_template": "SELECT emp.fname AS salesman_name, COUNT(*) AS order_count FROM t_sale_order so LEFT JOIN t_employee emp ON so.salesman_id = emp.fid WHERE ${orderDate:so.FDate} AND so.salesman_id = ${salesman_id} GROUP BY emp.fname",
      "params_mapping": {
        "salesman_id": "salesman_id"
      }
    }
  ]
}
```

**说明**:
- ✅ `${orderDate:so.FDate}`：日期参数由后端处理（自动转义+BETWEEN）
- ✅ `${salesman_id}`：业务参数由前端传递（穿透上下文）
- ❌ 不要在穿透SQL中使用其他业务筛选条件（如状态、客户名称等）
- ⚠️ 穿透SQL中的表别名必须与主查询一致（如 so.FDate）

**最佳实践**:
1. 穿透SQL仅包含必要的JOIN和WHERE条件
2. 日期参数使用 `${paramName:table.column}` 格式
3. 业务参数使用 `${paramName}` 格式，并在 params_mapping 中映射
4. 避免在穿透SQL中使用子查询或复杂聚合
```

**验收标准:**
- ✅ 文档清晰说明穿透SQL配置规则
- ✅ 示例代码可直接复用
- ✅ 标注了常见错误和最佳实践
